# Agent 内核

Agent 实现统一放在 `backend/app/agents/`，岗位发现和审批服务调用 `JobAgent.evaluate()`。不需要额外常驻服务、embedding 模型或向量数据库。

| 文件 | 职责 |
| --- | --- |
| `job_agent.py` | 创建上下文、运行执行器、保存成功或失败记忆 |
| `context.py` | 输入快照、观察、候选与最终结论、轨迹、模型输入预算 |
| `memory.py` | MemoryStore / Retriever 协议及 SQLite 记忆实现 |
| `planning.py` | Plan、PlanStep、Planner 协议及确定性岗位规划器 |
| `executor.py` | 逐步执行、观察后重规划、步数和总时限控制 |
| `tools.py` | 工具注册、参数校验、超时和权限检查 |
| `job_tools.py` | 岗位筛选、记忆读取、分析与反思工具组装 |
| `analysis.py` | 规则评分及可选的结构化模型分析 |
| `reflection.py` | 候选结论复核、修正及反馈 |
| `greeting.py` | 基于用户事实生成招呼语 |

## 计划、执行与反思

默认计划：硬规则筛选 → 读取记忆 → 生成候选分析 → 反思修正。规划器先生成计划，执行器每完成一步就保存观察并调用 `replan()`。硬条件不符时终止，不检索也不调用模型。默认最多 8 步、总耗时 120 秒，每个工具默认超时 45 秒；失败不自动重试。

当前 Planner 为确定性实现，不是模型自主规划；可注入实现 `Planner` 协议的模型规划器。Reflection 当前也采用确定性检查：核验硬条件和技能，移除越界、重复或无法关联技能的事实索引，补充待核实项，材料不足时将沟通建议改为人工复核。反馈写入记忆。它不保证识别模型文本中的所有错误，不替代人工审批，当前没有多轮模型自我反思。

## 上下文与记忆

每次调用深复制输入，不共享短期执行状态。模型输入优先保留完整当前岗位和个人资料，默认最多 32000 字符；超出时明确报错，不静默截断关键事实。历史摘要只使用剩余预算，字符预算不是精确 token 计数。

长期记忆写入现有数据目录的 `agent-memory.db`，默认保留最近 500 次执行摘要。保存轨迹、结果来源、反思反馈或错误类型，不保存密钥、异常原文和完整提示词。相同 run_id 防止重复写入；`forget(scope)` 删除指定范围，目前无独立界面入口。

范围绑定完整岗位和配置；资料改变后隔离旧记录。当前是严格范围匹配的执行记忆，不是语义检索或聊天历史系统。用户事实和审批检查点仍使用现有数据库。

未来 RAG 实现 `Retriever.retrieve(query, scope, limit)`，通过 `JobAgent(..., retriever=...)` 注入。记录须有 `source` 和 `text`；只能作为不可信参考，不自动变成用户事实。目前不实现文档导入、切分、embedding 和向量索引。

## 工具与审批

四个内置工具仅分析资料，不操作网页。Pydantic 校验参数；未知工具、未知参数和重复注册报错。分析执行器拒绝所有标记为写入的工具。

沟通和发送仍走已有 `ApplicationGraph` 的人工确认、Copilot 状态检查、岗位与回执核对，Agent 不能绕过。真实 BOSS 自动投递仍未启用。

## 验证

`backend/tests/test_agent_runtime.py` 覆盖上下文隔离、预算、记忆恢复与删除、工具权限与超时、执行上限、反思修正。原有招聘与桌面模拟测试继续验证审批发送闭环。
