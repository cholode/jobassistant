# Phase 3–4：岗位分析与确认投递

当前验收范围为本地模拟招聘站。真实 BOSS 只保留通用可见文本读取；其职位结构、聊天对象和发送回执尚无已验证适配器，因此禁止自动写入。没有自动上传简历、批量无人值守投递或招聘方回复处理功能。

## Phase 3

`jobs/parser.py` 将平台返回字段转换为岗位模型，生成稳定身份与内容指纹，解析经验和薪资。日薪不会当作月薪。`jobs/rules.py` 先检查岗位关键词、城市、经验、工作类型、薪资与黑名单，不符合规则时不调用模型。未知信息保留待核实。

`agents/job_agent.py` 支持规则分析与 LangChain 结构化模型分析。界面明确显示来源；规则分数仅为初筛参考。模型返回匹配建议、匹配点、材料缺口与事实索引。招呼语从用户原始事实及匹配技能组装，不直接采用模型自由生成的个人经历。缺口表述为“简历未体现”，不会断言用户不会。

使用模型需要在 `backend/.env` 配置 `OPENAI_API_KEY` 和 `JOB_AGENT_MODEL`；兼容服务可增加 `OPENAI_BASE_URL`。选择模型模式后缺少配置会明确报错，不会把规则结果伪装为模型结果。模型服务需支持结构化输出；真实服务调用仍需配置后验证。

## Phase 4

发现图：读取当前已加载页面 → 去重、规则过滤、分析、持久化。列表字段不足时要求打开详情；已有详情会保留，并按最新资料重新分析。当前最多处理本页 30 个职位，不自动翻页。

投递图：人工确认中断 → 校验岗位和配置 → 点击沟通 → 补充匹配消息 → 等待回复。拒绝确认直接结束。LangGraph SQLite 检查点支持重启后恢复待确认记录。

流程参照先前 BOSS 操作：先点击开始沟通，再补充岗位相关经历。每周天数和持续月数仅使用用户填写的承诺；到岗时间未确认时不会编造。默认城市不限、Go/Golang、经验一年以内、实习或正式工作、每日最多三次。实际资料以界面保存内容为准。

确认卡绑定岗位、完整配置和最终消息。配置变化要求重新生成；页面内容变化阻止操作。Electron 适配器再次验证岗位身份、目标会话及发送内容，每一步检查 Copilot 与运行状态。重复确认不会重复发送。沟通次数与间隔根据持久化尝试记录限制。

点击后超时、发送失败或执行中崩溃会标记结果不确定，禁止自动重试，需要人工查看会话。当前不发送附件，因此也不会在 HR 回复之前发简历。

## 分层

- React：`components/jobs` 展示资料、分析和确认卡；`useRecruitment` 管理异步数据。
- Electron：`ipc/recruitment` 固定接口代理；`MockApplicationAdapter` 封装 DOM 操作和回执。
- Python：`api` 接口、`services/recruitment` 用例、`jobs` 模型与规则、`agents` 分析、`graphs` 编排、`database` 持久化。

Agent 不持有 WebContents，也不能下发任意脚本或 CSS 选择器。未来 Qt 可继续实现同一浏览器语义协议。

## 验证与数据

运行根目录 `scripts/test.ps1`。覆盖审批前无动作、拒绝、暂停、页面变化、超时不重发、持久化恢复，以及真实 Electron 中的资料 → Go 岗位分析 → 确认沟通 → 补充消息闭环。测试仅使用模拟站，不联系真实招聘方。
