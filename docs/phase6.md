# Phase 6：自动任务与可追踪工作台

本阶段沿用 Python Agent / LangGraph / SQLite 和 Electron 平台适配器，新增 Auto、模型设置、历史、职位看板、聊天快照、执行追踪与异常核对。Phase 5 的自动回复和附件发送尚未实现。

## 使用

1. 在求职资料中保存技能、可对外陈述的真实经历、出勤及到岗安排。
2. 在模型设置中填写兼容接口地址、模型名与密钥，保存后可测试连接。留空密钥保留旧值，界面和 API 不返回密钥。
3. 打开完整职位详情，在“职位与投递”分析。缺口与反思仅给本人查看，不写入 HR 招呼语。
4. 单条使用 Copilot 确认卡；批量选择 Auto、恢复 Agent，在自动任务看板粘贴 BOSS 独立职位链接，也可勾选已分析岗位。设置目标数量后启动；候选链接会先读取详情、筛选和去重。
5. 默认开启“每投一岗停下来复盘”：发送回执核实后显示实际消息、匹配理由和私人缺口，填写意见后才会继续；发现问题可记录并停止。复盘时间计入投递间隔。候选耗尽与达到目标分别提示。
6. 历史查看消息、逐岗复盘与状态；沟通消息保存当前网页会话；追踪查看工具步骤、反思和持久事件。

每日上限为 0 表示不额外设置本地次数上限；仍检查投递间隔、平台限制和队列范围。每次队列最多选择 100 个岗位，不代表全局投递总量限制。

## 执行约束

- Auto 只处理本次明确选择的岗位，重新评估当前资料；需要复核的岗位停止自动队列。
- 岗位、资料、消息、会话和操作编号相互绑定；已有投递记录不重复执行。
- 点击之后缺少回执记为 UNCERTAIN；历史中人工核对后归档，不自动重发。
- 暂停、断线、配置变化和平台验证都停止下一步。应用重启不会自动继续队列。
- 不足、concerns、reflection 不进入对外招呼语；消息只引用确认的事实、匹配技能与到岗条件。
- 不发送附件，也不自动回复 HR。聊天快照只包含已加载内容，不保证完整聊天历史。

## 分层

- `backend/app/services/auto_run.py`：队列、配置绑定、终止和运行状态。
- `backend/app/services/application_review.py`：生成仅本机保存的逐岗复盘卡。
- `backend/app/services/console.py`：看板、历史、聊天归档、异常核对。
- `backend/app/services/model_settings.py`：本地模型配置和脱敏连接测试。
- `backend/app/api/console.py`：固定 HTTP 接口。
- `client/electron/platforms/boss/`：BOSS 详情、当前会话读取和带回执校验的沟通适配器；不能识别的页面停止。
- `client/src/components/jobs/ConsolePanel.tsx`、`ModelSettingsForm.tsx`：工作台和模型设置界面。
- `client/src/components/jobs/AutoQueuePanel.tsx`：候选链接、目标进度、复盘表单与队列记录，独立于工作台容器。

业务数据库、Agent 记忆、运行状态和模型设置位于本机私有数据目录（开发版 `private/`），均不提交 Git。模型密钥当前保存为本机私有 JSON，不声称具备系统凭据库加密。

## 逐岗检查流程

执行顺序为：导入候选 → 读取详情 → 硬条件筛选 → 模型分析与 Reflection → 绑定当前岗位和资料 → 开始沟通 → 核对当前公司与岗位 → 发送真实经历介绍 → 核对己方回执 → 保存本岗复盘 → 放行下一岗。

人工操作会结合岗位业务选项目、留意招聘者活跃度和正文里的额外条件；Agent 通过结构化条件及事实引用执行。现在额外检查明确的截止日期，长期不活跃转为待复核；算法岗位保留竞赛证据，实习和校招展示用户已确认的学校及届别。复盘仍需检查介绍针对性、时间和学历条件、正文与标题是否矛盾。模型匹配分不是录用概率；HR 活跃度尚未自动用于排序。发现问题先停止，再修改与验证，不能把“按钮点击成功”当作“消息发送成功”。

## 回归测试

运行 `./scripts/test.ps1`。后端覆盖队列重复保护、暂停、资料变化、模型配置脱敏、异常核对及消息不泄漏分析缺口。桌面测试使用独立数据目录，验证 IPC / HTTP / WebSocket 完整流程；BOSS 契约页通过网络路由替换为离线测试数据，绝不向真实公司发送测试消息。真实投递需另外在已登录平台核对实际回执，不能用离线测试冒充。

2026-10-04 本轮新增 20 个真实岗位沟通，每次发送后均单独评估：18 次 Agent 完成发送，2 次会话识别失败后人工接管；没有发送附件或向 HR 披露私人缺口。每条均核实发送回执，不代表已读、回复或录用。

实战中修复了 Go 与中文相邻时误筛、按 HR 头衔枚举造成会话漏识别、相关项目事实被 Reflection 误删，以及算法证据和届别遗漏。会话现在按详情页的公司身份定位，发送前仍核对岗位与操作编号。另补充截止日期、长期不活跃、组合技术栈缺少依据和实习正文要求工作年限的检查。测试过程中仍出现过筛选质量问题，报告保留原始复盘，不把已发送等同于完全匹配。

45 项后端测试、3 项浏览器 RPC 测试和桌面端完整流程均通过。具体公司、实际消息和私人缺口见开发版 `private/agent-pilot-20-2026-10-04.html` 与同名 JSON，均被 Git 忽略。未投递的剩余候选不会在重启后自动执行。
# 招聘者活跃度筛选

BOSS 自动沟通仅接受招聘者名片（头像旁）的七天内活跃状态，包括在线、今日活跃、3 日内活跃、7 天内活跃。超过七天、月内活跃、近期活跃、缺失或冲突状态均跳过。状态作为独立字段保存，在模型分析前以及执行沟通前检查；不能使用职位正文或推荐岗位中的活跃字样替代。页面读取面板展示实际读取的状态。

100 岗实战期间进一步补充沟通语境复核（`backend/app/jobs/review.py`）：招聘公司明确出现在既往任职经历、正文中文截止日期早于当前日期，均转人工复核。没有年份的截止日期按本年比较并明确标注不确定性，不直接断言招聘已结束。当前支持中文年月日格式；并非所有自然语言截止信息都能确定性识别。

模型上下文包含北京时间日期、完整已确认求职偏好及可用时间；分析提示明确区分任选技能、优先项与硬门槛，禁止凭空制造专业、实习时长、城市和学业冲突。截止与既往雇主另经 Reflection 二次校验。本科材料遇到硕博学历标签、正文又未明确接受本科时，同样转复核；实习开场支持从“预计某年某月毕业”提取真实学校和毕业时间。兼职标题直接拦截，明确毕业年份不匹配转复核；模型模式不再叠加忽略语境的技术关键词缺口。新增回归后，78 项后端测试通过；模型对开放文本的判断仍须逐岗复盘。

## 完整聊天页兼容与验证边界

开始沟通可能跳转完整聊天页，桌面只读等待最长 15 秒，后端该指令响应期限 25 秒；不会重复点击。消息列表必须可见且位于输入框之前，排除工具栏隐藏菜单。完整聊天页不再依赖 HR 头衔枚举，发送前仍核对公司、岗位和操作编号。富文本采用 Chromium 原生输入，避免文字显示在输入框中但网页编辑器未同步。

离线回归覆盖延迟初始化、CTO 头衔、隐藏菜单与原生输入事件。最后一轮原计划新增 20 个岗位，实际只确认 1 个发送成功后由用户停止；其他异常不计成功，未自动重发。最后的富文本修复尚待下一次获授权实投验证，不将离线通过视为真实平台全部适配完成。
